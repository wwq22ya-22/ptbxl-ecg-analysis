# ECG 项目小组成员阅读指南

更新：2026-10-14。本文用于帮助组员了解项目、查找文件和选择正确的演示版本。仓库地址：[ptbxl-ecg-analysis](https://github.com/wwq22ya-22/ptbxl-ecg-analysis)。

## 1. 先了解项目在做什么

本项目使用 PTB-XL 公开数据库中的十二导联心电波形，识别 NORM、MI、STTC、CD、HYP 五类诊断，并将轻量模型部署到 STM32F407VG。

每次输入是一段 10 秒、100 Hz 的十二导联波形，共 12000 个数。输出是五个独立概率，一条记录可以同时有多个阳性标签，也可以没有标签达到阈值。界面虽然一次显示一条导联，实际发送全部十二导联。

| 标签 | 含义 |
|---|---|
| NORM | 正常心电诊断 |
| MI | 心肌梗死诊断大类 |
| STTC | ST/T 改变 |
| CD | 传导异常 |
| HYP | 肥厚诊断大类 |

当前展示使用数据库波形回放，不包含人体心电采集设备。当前上板模型为 **100 Hz、seed44 蒸馏 CNN、INT8、原部署阈值**。

## 4. outputs 目录怎么找

outputs 里保留了多次实验。**文件夹多不代表这些模型都部署到了板上**；查找时先按用途定位。

### 4.1 当前演示和部署最常用的目录

| 目录 | 内容 |
|---|---|
| [`outputs/board_release/`](../outputs/board_release/) | HEX、完整源码 ZIP、使用说明、资源与文件哈希清单 |
| [`outputs/distillation/`](../outputs/distillation/) | 学生模型、蒸馏结果、ONNX、串口演示样本及各套 Keil 工程 |
| [`outputs/serial_samples/`](../outputs/serial_samples/) | 折10回放清单、核对结果、真实上板日志和计时记录 |
| [`outputs/validation_only_redo_20261010/`](../outputs/validation_only_redo_20261010/) | 后续验证选模结果及 seed43 候选；没有替换当前板上模型 |
| [`outputs/publication_20261014/`](../outputs/publication_20261014/) | 发布前验证记录、当前部署对最初基线的同人群对照 |

`distillation` 中三个 VG 工程分别是：

- [`stm32_student_project_vg`](../outputs/distillation/stm32_student_project_vg/)：A 文本版，只在板端执行量化和推理。
- [`stm32_student_raw_vg_project`](../outputs/distillation/stm32_student_raw_vg_project/)：B 版，板端预处理再推理。
- [`stm32_student_fast_vg_project`](../outputs/distillation/stm32_student_fast_vg_project/)：A Fast 版，二进制 INT8 传输。

### 4.2 查模型和成绩的目录

| 目录 | 内容 |
|---|---|
| `checkpoints` | 最初正式模型权重 |
| `metrics` | 最初正式模型的整体、逐类成绩及训练历史 |
| `predictions` | 最初正式模型对每条记录的预测 |
| `figures` | 保存的训练和评价图表 |
| `stm32` | 早期模型导出文件；当前学生部署优先查 distillation 和 board_release |
| `reports` | 数据划分、标签分布等技术审计；个人开题报告和周记不在这里 |

后续实验通常也会在自己的目录内保存检查点、配置、预测和指标，因此不能只在根目录的 metrics 中找所有模型成绩。跨实验查看时先打开[指标总表](各模型整体与逐类指标总表.md)。

### 4.3 各类实验目录

| 目录 | 对应的研究内容 |
|---|---|
| `optimization` | 标准化、损失及网络等第一轮优化 |
| `further_optimization` | 后续损失、增强、池化和集成比较 |
| `cross_validation` | 患者内部留出比较 |
| `diagnostic_only` | 按五类诊断标签筛选后的重训结果 |
| `teacher_preprocessing` | 预处理与教师网络比较 |
| `teacher_distillation` | 后续教师到轻量学生的蒸馏研究 |
| `noise_robustness_b` | 白噪声鲁棒性实验；这里的 b 不代表 B 板端预处理固件 |
| `ribeiro_teacher` | Ribeiro 文献网络的本项目适配实验 |
| `unet_teacher_20261010` | U-Net 与编码器对照、两人群及三种子结果 |
| `highrate_study_20261010` | 250/500 Hz 与既有 100 Hz 的性能和资源比较 |
| `student_threshold_refinement` | 学生模型逐类阈值研究 |
| `unfiltered_threshold_refinement` | 筛选与未筛选队列的阈值和评价比较 |

实验目录用于查证据。需要当前固件时直接去 board_release，不要按实验文件夹日期最新就认定已经换了部署模型。

## 5. 当前到底用哪个模型、哪个固件

三个 VG 版本均使用 seed44 INT8 和原阈值 `[0.55,0.60,0.55,0.75,0.65]`，主要区别是预处理位置和传输方式。

| 版本 | 数据怎样进入板子 | 板端做什么 | 当前验证状态 |
|---|---|---|---|
| **A 文本版** | 电脑预处理，发送浮点文本 | 量化、推理、五类判断 | **已完成小批真实上板** |
| B 板端预处理版 | 发送原始 mV 浮点波形 | 去基线、带通、标准化、量化、推理 | 已编译与主机核对，未实板 |
| A Fast 快速版 | 电脑预处理和量化，发送二进制 INT8 | 推理、五类判断 | 已编译与主机核对，未实板 |

当前已验证的 A 版对应：

- [VG A 烧录包](../outputs/board_release/seed44_int8_stm32f407vg/)。
- [A 版 HEX](../outputs/board_release/seed44_int8_stm32f407vg/ECG_Student_INT8_STM32F407VG.hex)。
- [学生上位机启动器](../start_ecg_student_viz.cmd)。
- [上位机 Python 入口](../scripts/ecg_stm32_viz.py)。

名字带 `stm32f407ve` 的目录是旧 VE 回退包；当前 VG 板优先使用对应 VG 工程。seed43 是算法优化候选，尚无完整新固件，不能直接替换 HEX。教师模型用于训练学生，不是当前板上运行的网络。

2026-10-11 的 A 实板验证回放了 3 条不同记录及 1 次重复，返回网络推理时间 **1012–1013 ms**，与电脑 C 参考最大概率差约 **3.006e−8**；整次文本收发为 **16.50–16.97 秒**。这证明小批样本的板端推理与输出一致性，不等于分类准确率 100%，也不等于完整队列或长期稳定性通过。

原始证据：[实板回放](../outputs/serial_samples/seed44_fold10/physical_inference_check_20261011_103033.json)、[独立计时](../outputs/serial_samples/seed44_fold10/physical_timing_audit_20261011_103850.json)。旧发布清单中的 `physical_board_test=false` 记录的是构建时状态，后续实板证据以这些单独日志为准。

## 6. 筛选数据、模型成绩应该怎样理解

### 筛选规则

当前 seed44 使用筛选后数据：训练 **17084** 条、验证 **2146** 条、历史测试 **2158** 条。保留五类中至少一类有标签的记录；五类全零的记录排除。**NORM 本身是目标标签，所以正常心电仍然保留。**

筛选依据是任务标签覆盖，不能说成删除预测错误或质量差的样本。只有节律/形态标注而没有五类诊断标注的记录，不能直接视为五类全部阴性的可靠证据。作者基准的五大诊断类任务也会排除目标诊断标签为空的记录，见[作者代码](https://github.com/helme/ecg_ptbxl_benchmarking/blob/master/code/utils/utils.py#L243-L251)。

未筛选数据用于对照和检查范围外输入表现，没有替换当前部署模型。250/500 Hz 也属于研究比较；当前固件仍是 100 Hz。

### 常用成绩与统计范围

| 项目 | 数值 | 应怎样表述 |
|---|---|---|
| seed44 INT8，原部署阈值，筛选后验证集 | Macro F1 75.459% | 当前部署模型的验证成绩 |
| seed44 INT8，研究细阈值，同一验证集 | Macro F1 75.683% | 阈值研究结果，未同步现有 HEX |
| seed43 INT8，自身阈值，同一验证集 | Macro F1 75.893% | 后续候选的验证成绩 |
| seed44 INT8，原部署阈值，筛选后历史测试集 | Macro F1 74.944%，Macro Recall 75.959% | 历史探索结果 |
| 与最初 CNN 在相同 2158 条上的比较 | F1 +3.832、Recall +1.602 个百分点 | 完整方案变化，不归因于单一改动 |

Macro F1 是五类各自计算 F1 后取平均，不能改称“准确率”；Recall 反映阳性检出比例，需要结合 Precision 和误报解释。不同队列、阈值、精度或数据集的成绩不能直接混排。

fold 9 用于验证和选择，fold 10 在历史研发中已反复使用，因此现有 fold 10 数字不作为新的独立盲测。Chapman 主结果只支持四类明确阳性 Recall，NORM 未计分，不能写成完整五类外部验证。

## 7. 组员怎样开始操作

### 只看说明和结果

直接在 GitHub 打开本指南和上面的文档即可，不需要安装 Python、下载完整数据库或重新训练。已有 HEX 和源码包从 board_release 下载。

### 在自己的电脑打开 A 上位机

先克隆或下载完整仓库并解压，不要只下载单个 Python 文件。在项目根目录打开 PowerShell，按本机可用的 Python 环境执行：

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r requirements-train.txt -r requirements-stm32.txt
.\start_ecg_student_viz.cmd
```

仓库保留 128 条 fold 9 演示样本，基础串口演示不必下载完整数据库。打开窗口只代表电脑程序已启动；真实通信还需要正确固件和串口接线。

当前 A 使用 USART1：PA9/TX 接 USB 转串口 RX，PA10/RX 接 TX，GND 共地，3.3 V TTL、115200/8N1。选择实际 COM 口，确认模型握手成功后发送。COM8 是原实验电脑的端口号，其他电脑可能不同。

烧录前核对 VG 目标、板载晶振和相应工程配置；现有工程按 8 MHz HSE、168 MHz CPU 编译。HEX 应下载原始文件，不要复制网页文本另存；烧录与接线按[部署说明](STM32部署与串口验证.md#deployment-run)执行。

### 查阅或重建完整数据

完整数据库和大型缓存没有随 GitHub 提供。折10完整波形包也未上传，需按[发布说明](GitHub同步与实板验证.md)和[数据说明](../data/README.md)在本机重建；部分参考生成需要 ST 工具。模型、清单和日志可以直接查看，不代表全部实验都能在无数据环境下一键复现。

## 8. 常见文件后缀与协作约定

| 文件后缀 | 是什么 | 怎么使用 |
|---|---|---|
| `.md` | 说明文档 | GitHub 或编辑器阅读 |
| `.py` | 电脑程序 | 用项目 Python 环境运行 |
| `.c`、`.h` | STM32 或主机验证源码 | 在对应工程中编译 |
| `.pt` | PyTorch 模型检查点 | 由模型程序加载 |
| `.onnx` | 导出的模型交换文件 | 用于推理或 STM32AI 转换，不是直接烧录文件 |
| `.hex` | 已编译的固件 | 用下载器烧录到匹配的 MCU |
| `.uvprojx` | Keil 工程入口 | 用 Keil 打开，查看或重新编译 |
| `.zip` | 完整源码或其他归档 | 下载并解压，按包内说明使用 |
| `.json` | 参数、成绩、清单或日志 | 查看字段；具体用途看文件名和上级目录 |
| `.csv` | 表格数据、预测或样本清单 | 用表格软件或文本工具查看 |
| `.npz`、`.npy` | 数值数据、波形或预测缓存 | 由 Python 程序读取 |
| `.png` | 图表 | 直接查看 |

`seed44` 是训练随机种子的版本标识，不是第 44 代模型。FP32 为浮点版本，INT8 为低精度量化版本；文件名里出现 INT8 也不能代替完整精度与板端验证。

组内交流和修改时，建议遵守以下约定：

- 说清使用哪个模型、阈值、采样率、训练人群和评价集合；“当前部署”统一指 seed44 INT8 原部署阈值。
- 每套上位机与对应 A／B／Fast 固件配对，不能只换电脑程序就认为固件功能也改变。
- 修改模型或预处理时同步配置、清单、量化参数和阈值；原始日志、原模型与可回退固件保留。
- 新实板实验保存记录 ID、固件/模型身份、参考与板端结果、运行模式和耗时，按实际范围更新状态。
- 个人开题报告、周记及其附件不上传；完整数据、环境和本机缓存也不提交。

后续主要工作是 B／Fast 实板验证、扩大 A 的回放范围、分项耗时和栈峰值测量，以及连续运行与异常恢复检查。当前状态和原始证据以[部署说明](STM32部署与串口验证.md)及对应日志为准。
