# 项目任务（优化版）：基于 PTB-XL 的十二导联 ECG 智能分析与可视化系统

> 本文是一份可直接交给开发 Agent 执行的项目任务书。当前任务是完善开发流程；本文件本身不代表系统已经实现或训练完成。

## 1. 角色与最终目标

你是本项目的主要开发 Agent。请在当前工作目录中实际创建、运行和验证一个基于 PTB-XL 的十二导联 ECG 分析系统。最终交付应包含：数据读取、波形展示、基础信号分析、五类多标签深度学习分类、真实评估、单条记录推理、Streamlit 界面、FastAPI 接口、测试和完整 README。不能只交方案、代码片段或 Notebook。

项目供教学和科研演示使用。界面和文档统一使用“AI 分类结果”或“模型预测”，不得宣称临床诊断，不得把短时 HRV 或显著性图解释为医疗结论。

目标运行环境：Windows、NVIDIA RTX 4060 Laptop GPU（8 GB 显存），支持 CPU 回退。优先选用 Python、PyTorch、NumPy、Pandas、SciPy、scikit-learn、WFDB、matplotlib、Streamlit、FastAPI 和 Uvicorn。建立项目专用虚拟环境，不能改动系统级 Python。

## 2. 开始前的检查与参考分析

先检查当前目录、已有用户文件、Python 与 pip、Git、GPU/CUDA、可用磁盘空间和网络条件。保留现有文件；如目录为空，就在当前目录直接创建项目，不再套一层同名目录。给出简短检查结果和实施顺序，然后开始执行，不因普通技术选择反复停下来询问。

阅读参考项目 [AndrewLucenko/ptb-xl-ecg-classification](https://github.com/AndrewLucenko/ptb-xl-ecg-classification)，重点核对数据路径、官方 folds、标签聚合、模型、损失、训练、评估、API、模型文件和许可。形成简短的“借鉴 / 重写 / 扩展”记录。可以借鉴模块划分和验证思路，但独立实现；不得复制其已训练权重、测试结果或演示样本选择作为本项目成绩。README 写明参考项目、PTB-XL 来源、论文和实际复用代码的许可归属。

## 3. 数据与可复现约定

使用 [PTB-XL 官方数据集](https://physionet.org/content/ptb-xl/1.0.3/)的 WFDB 文件。默认使用 `records100`（100 Hz、10 秒、每导联 1000 点），允许将来切换 `records500`。数据目录默认 `data/ptb-xl/`，可由配置或命令行覆盖；通过 `ptbxl_database.csv` 的 `filename_lr` / `filename_hr` 字段定位波形，不拼猜文件名。

若数据不存在，程序应给出数据集名称、官方链接、期望目录和缺失文件清单。数据准备脚本可支持官方来源的下载与完整性检查；下载失败时给出可手动完成的步骤，不吞掉异常，也不生成假 PTB-XL 数据。小型合成信号仅供单元测试和无数据的信号处理演示，必须清楚标注，不能用于报告模型性能。原始数据、虚拟环境和大模型文件默认加入 `.gitignore`。

数据划分直接使用官方 `strat_fold`：1–8 为训练集、9 为验证集、10 为测试集。核查患者不跨集合；不重新随机拆分。解析 `scp_codes`，仅通过 `scp_statements.csv` 中的诊断映射聚合为 `NORM`、`MI`、`STTC`、`CD`、`HYP` 五个 superclass；一条记录允许多个标签。记录类别数量及无目标标签记录的处理规则。测试集只在模型、阈值和配置确定后用于最终评价。

训练、验证、测试和单条推理必须使用同一版本的导联顺序、采样率、预处理与归一化规则。任何需要估计的全局统计量只从训练集计算，并随 checkpoint 保存。默认按需读取波形，DataLoader 按 batch 加载，避免一次把全量数据放进 GPU。

## 4. 分阶段实施与验收

每阶段遵循“实现最小可用功能 → 运行针对性检查 → 修复错误 → 记录真实结果 → 进入下一阶段”。不要先铺开几十个文件，再集中测试。

### 阶段 A：项目骨架与数据通路（P0）

建立配置、依赖、`.gitignore`、数据说明、模块化 `src/`、脚本、测试和输出目录。实现 metadata reader、WFDB waveform loader、标签解析、fold 划分和 Dataset。读取一条记录应得到明确的 `samples × 12 leads` 数组、采样率、单位和导联名 `I, II, III, aVR, aVL, aVF, V1–V6`；训练张量转换为 `[B, 12, T]`。

实现 Lead II 单导联和十二导联波形图，时间轴按采样率计算，幅值轴按 WFDB 返回的物理单位标注。验收：真实 PTB-XL 记录（若已下载）可读取和绘图；无数据时缺失提示可读；使用小型固定测试样本验证形状、导联顺序、标签映射和 fold。

### 阶段 B：信号处理与医学量测（P0）

实现可配置的基线漂移处理、ECG 带通滤波、归一化、R 峰检测、RR/心率和时域 HRV（Mean RR、SDNN、RMSSD）。对滤波截止频率、阶数、零相位处理、边界效应与短信号行为作简短说明。保留原始波形用于对照；分类模型所用预处理应固定、可追溯，避免把用于 R 峰检测的滤波参数无条件套到分类输入上。

工频陷波可选 50/60 Hz，但必须检查采样率与 Nyquist 频率：对 100 Hz 波形不能直接做 50 Hz 陷波，60 Hz 也超出 Nyquist；需要工频抑制时使用 500 Hz 原始记录先处理，再按规定下采样，或在 100 Hz 流程中跳过并明确说明。不能接受无效参数后静默输出。

R 峰检测至少有一个可解释的实现，例如滤波、增强 QRS、候选峰、最小间隔和异常检查。输入 ECG 与 `fs`，输出峰索引及质量提示，并显示波形上的峰标记。由有效 RR 计算心率，处理不足两个峰、过短记录、不合理 RR、噪声和异常峰；不能在失败时给出看似正常的数值。PTB-XL 是 10 秒记录，HRV 仅作算法演示，界面必须显示“当前 ECG 记录长度有限，该结果仅用于算法演示，不应作为临床长期 HRV 评价。”验收：用有已知峰位置的合成信号与至少一条真实记录验证峰位、单位、RR/HR 计算及异常输入。

### 阶段 C：CNN 基线、训练与评估（P1）

先完成小型 1D CNN：`Conv1d → BatchNorm → ReLU → Pooling/Conv blocks → Global Average Pooling → 5 logits`。使用 `BCEWithLogitsLoss`，推理时对 logits 独立做 sigmoid；绝不使用互斥 softmax。类别不平衡先统计训练集标签分布，再考虑仅依据训练集计算 `pos_weight`，记录公式与取值。阈值放在配置或验证产物中，不写死进模型；如调每类阈值，只能用验证集。

训练支持随机种子、CPU/GPU 自动选择、保守的默认 batch size（例如 16）、学习率和 epoch 配置、按 batch 加载、CUDA AMP、early stopping、最佳 checkpoint、续训所需元数据和清晰的 OOM 提示。checkpoint 至少包含模型结构标识、权重、导联顺序、采样率、预处理与归一化配置、标签顺序、阈值、随机种子和训练/验证摘要。先跑小样本 smoke run，再跑可承受的完整训练；不得把 smoke run 的指标写成完整实验结果。

评估至少报告每类 AUROC、Precision、Recall、F1，以及 Macro AUROC 和 Macro F1；同时绘制每类 ROC、二分类混淆矩阵、训练/验证损失与类别分布。单类在某个划分中缺少正例或负例时，AUROC 标为不可计算并解释。保存机器可读指标和图表，记录数据版本、fold、样本数、checkpoint、阈值和运行设备。只有真实完整测试后才能在 README 写测试指标，否则写 `Not yet evaluated`。

### 阶段 D：单条推理与 Streamlit 演示（P2）

实现单条 PTB-XL 记录推理，输出五个概率及按阈值确定的 positive labels；检查输入形状、采样率、导联顺序和单位。无 checkpoint 时，界面仍可展示已有数据与信号分析，并明确提示分类不可用，不制造概率。

Streamlit 至少提供：项目概览、十二导联查看、原始/滤波波形与 R 峰、HR/RR/HRV、五类概率柱状图、真实评估图表。对缺数据、缺 checkpoint、缺评估结果分别显示可操作的提示。所有“预测”和“参考标签”明确区分；允许选择记录，但不要只展示挑出的正确案例而暗示总体性能。

### 阶段 E：API、解释性与进阶模型（P3）

提供 FastAPI `GET /health`（服务状态、模型是否加载、设备）和 `POST /predict`（约定好的 JSON 数组及采样率、导联顺序，返回概率和阈值标签）。使用与 Streamlit 相同的推理服务；请求校验失败给出明确 4xx 错误。接口可启动并通过最小请求测试。

再实现一个稳定、简单的解释性方法，如输入梯度显著性，并把模型响应覆盖到 ECG 时间轴上；明确标注它不等于临床因果解释或医生判断。1D ResNet 作为基线稳定后的独立实验，沿用同一数据划分和评估流程；CNN+Attention 仅在时间与资源允许时添加。不得为了扩展模型影响基线可运行性。

最低可演示闭环：真实 PTB-XL 记录 → 十二导联查看 → 滤波及 R 峰/RR/HR/HRV → CNN 推理概率 → Streamlit 展示，并有能启动的 API。核心测试至少覆盖加载器、标签/fold、滤波边界、R 峰、心率、模型前向、推理输出和 API 健康检查。每完成一个阶段就运行相应测试与入口，不隐藏失败。
